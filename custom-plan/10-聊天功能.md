# 10 - 聊天功能 (Chat)

## 概述

基于现有 SSH 结构，添加类似 IRC 的聊天机制。用户通过 SSH 公钥认证后，使用 `/chat` 命令进入聊天模式。

## 需求确认

| 需求项 | 决定 |
|--------|------|
| 身份认证 | 使用现有 SSH 公钥认证 |
| 消息持久化 | 持久化到文件系统（JSONL 格式） |
| 频道持久化 | 持久化到文件系统（JSONL 格式，追加写入） |
| 历史查询 | 默认 7 天，支持时间范围参数 |
| 频道管理 | 混合模式（默认 #general + 用户自建） |
| 界面形式 | 简单命令行 |
| 高级特性 | 仅 /topic 频道主题 |

## 设计约束（简化实现）

| 约束项 | 说明 |
|--------|------|
| 消息已读状态 | 通过 mark 消息记录读取位置 |
| 消息 ID | 全局唯一，时间戳 + 流水号 |
| 频道 topic 权限 | 任何人都可设置 |
| 频道/消息删除 | 不支持，一旦写入不可删除 |
| 用户在线状态 | 不监控 |
| 消息撤回/编辑 | 不支持 |
| 事件与消息混合 | 刻意设计，便于回放完整历史 |
| 消息投递 | 三副本：发件箱、收件箱、确认回执 |

## 规范遵循

**本设计遵循 RFC 5322 (Internet Message Format) 规范。如文档中任何设计与 RFC 5322 冲突，以 RFC 5322 为准。**

主要遵循的 RFC 5322 规范：
- 消息 ID 格式和唯一性要求
- `Reply-To` 和 `References` 头字段的语义
- 消息头字段命名约定
- 日期时间格式 (RFC 5322 Section 3.3)

## 技术决策

### 数据格式规范

| 决策项 | 决定 |
|--------|------|
| **消息 ID 格式** | `YYYYMMDDHHmmss-NNN`（如 `20250115100200-001`） |
| **时间戳时区** | 本地时间 |
| **JSON 编码** | 遵循业界规范（标准 JSON 编码） |
| **消息长度** | 不限制 |

### 并发与一致性

| 决策项 | 决定 |
|--------|------|
| **进程模型** | 单进程处理（不支持多实例） |
| **部分失败处理** | 可重试，重复投递只生效一次（幂等） |
| **回执失败** | 同样幂等，可重试 |
| **文件损坏** | 删除损坏的行，保留有效数据 |

### Mention 解析规则

| 决策项 | 决定 |
|--------|------|
| **解析策略** | 最大匹配 |
| **分隔要求** | `@mention` 前必须是空格或显著标点符号 |
| **邮箱排除** | `xxx@gmail.com` 不产生 mention |
| **中文支持** | 支持，使用最大匹配 |
| **全角支持** | 支持 `＠`（全角 @） |

```
# 示例
"hello @bob"         → mention: bob
"hello@bob"          → 无 mention（无分隔）
"email: bob@xx.com"  → 无 mention
"你好 @张三"          → mention: 张三
"hello ＠bob"        → mention: bob（全角 @）
"@alice@bob"         → mention: alice（最大匹配）
```

### 实时推送

| 决策项 | 决定 |
|--------|------|
| **推送顺序** | 以消息 ID 为序列 |
| **上线后** | 主动拉取未读消息 |
| **新消息** | 实时推送给在线用户 |

### 多设备与回执

| 决策项 | 决定 |
|--------|------|
| **多设备** | 理论上一个用户一个 SSH 连接 |
| **多连接处理** | 多个连接都执行推送，不区分 |
| **接收消息** | 视作同一个连接，不区分来源 |
| **ack 回执** | 自动确认 |
| **批量操作** | 不支持 |

### 运维与兼容性

| 决策项 | 决定 |
|--------|------|
| **数据迁移** | 不考虑 |
| **版本兼容** | 不考虑 |
| **备份** | 用户自行处理 |

### 首次进入与订阅

| 决策项 | 决定 |
|--------|------|
| **首次进入聊天** | 不自动订阅任何频道，需手动 `/join` |
| **订阅已订阅频道** | 忽略，不生效 |
| **订阅时 cursor** | 调用 `GetLastChannelMsgID()` 获取当前最新消息 ID |

### Mention 已读

| 决策项 | 决定 |
|--------|------|
| **Mention 已读标记** | 逐个标记（可使用临时编号便于操作） |
| **Mark inbox 格式** | `#channel`（频道）或 `@user`（私聊）或 `mention:ID`（单条 mention） |

### 推送机制

| 决策项 | 决定 |
|--------|------|
| **推送关系维护** | 内存维护 `map[channel][]*ChatSession` |
| **新会话关联** | 会话创建时，检索用户订阅的频道，关联到对应 channel 列表 |
| **推送失败** | 重试 N 次后记录日志，静默放弃 |
| **重试次数** | 3 次（可配置） |

### 频道成员

| 决策项 | 决定 |
|--------|------|
| **成员来源** | join/leave 事件 + 快照重建 |
| **成员用途** | 重建推送关系（新会话创建时） |

### 消息引用

| 决策项 | 决定 |
|--------|------|
| **References 处理** | 参考邮件处理方式（RFC 5322）和 Linux B4 工作流 |
| **跨频道引用** | 不支持 |
| **跨私聊引用** | 不支持 |

### 未读计数

| 决策项 | 决定 |
|--------|------|
| **计数方式** | 扫描文件 + LRU Cache |
| **Cache 大小** | 1000 条（可配置） |

### 实现细节

| 决策项 | 决定 |
|--------|------|
| **布隆过滤器** | 移除，仅保留接口 |
| **文件锁** | `sync.Mutex`（进程内）+ 文件锁（跨进程安全） |
| **邮箱大小** | 不限制，理论上单文件不超过 1MB |


### 命令说明

| 规则 | 说明 |
|------|------|
| @mention | 在频道消息中提及用户，用户会收到通知 |
| 私聊语法 | 必须使用 `/dm @user xxx`，不能直接 `@user xxx` |
| 自动 join | 向未加入的频道发送消息时，自动加入该频道 |
| 不存在的用户 | mention 不存在的用户时，静默忽略（不写通知） |
| 频道名格式 | `#[a-zA-Z0-9_-]+`，最长 50 字符 |
| 用户名格式 | 来自 SSH 认证，不支持特殊字符 |

```go
// pkg/chat/user_list.go

// UserList 用户列表来源
type UserList interface {
    Contains(name string) bool
    List() []string
}

// EnvUserList 从环境变量读取用户列表
// 环境变量格式：SOFT_SERVE_CHAT_USERS=alice,bob,carol
type EnvUserList struct {
    users map[string]bool
}

func NewEnvUserList(env string) *EnvUserList {
    users := make(map[string]bool)
    for _, name := range strings.Split(env, ",") {
        name = strings.TrimSpace(name)
        if name != "" {
            users[name] = true
        }
    }
    return &EnvUserList{users: users}
}

func (l *EnvUserList) Contains(name string) bool {
    return l.users[name]
}

func (l *EnvUserList) List() []string {
    names := make([]string, 0, len(l.users))
    for name := range l.users {
        names = append(names, name)
    }
    return names
}
```

## 邮箱模型

### 设计理念

- **频道邮箱** (`#channel.jsonl`): 存储频道消息和事件
- **用户邮箱** (`@user.jsonl`): 存储私聊、订阅、通知、读取标记、状态快照
- **标记已读** = 给自己发一封包含 cursor 的邮件
- **状态快照** = 定期将当前状态打包，避免重建时回溯过多
- **三副本投递** = 发件箱 + 收件箱 + 确认回执，确保最终一致

### 消息投递模型（三副本）

```
Alice 发送私聊给 Bob：消息 ID = "20250115100200-001"

1. 发件记录 → @alice 邮箱（Alice 的发件箱）
   {"type":"dm","id":"20250115100200-001","direction":"out","to":"@bob","content":"hello",...}

2. 收件记录 → @bob 邮箱（Bob 的收件箱）
   {"type":"dm","id":"20250115100200-001","direction":"in","from":"@alice","content":"hello",...}

3. 确认回执 → @alice 邮箱（Bob 收到的确认，当 Bob 读取时）
   {"type":"ack","id":"20250115100200-001","inbox":"@bob","ts":"..."}

规则：
- 消息 ID 全局唯一，重复投递不会产生重复记录
- 查询时通过 ID 去重，确保数据最终一致
- ack 是可选的，用于支持"已送达"状态
```

### 频道消息与 @mention

```
Alice 在 #general 发送： "@bob please review this"

1. 频道邮箱 #general.jsonl
   {"type":"msg","id":"20250115100200-001","from":"alice","content":"@bob please review this","mentions":["bob"],...}

2. 被提及者的用户邮箱 @bob.jsonl（通知）
   {"type":"mention","id":"20250115100200-001","inbox":"#general","from":"alice","content":"@bob please review this",...}

规则：
- 频道消息中检测 @username，生成 mention 记录
- mention 记录写入被提及者的用户邮箱
- 用户可以通过 mention 类型消息快速定位重要消息
```

### 用户邮箱消息类型

```go
// pkg/chat/message.go

type UserMessageType string

const (
    // 消息类
    UserMsgDM       UserMessageType = "dm"       // 私聊消息（收/发）
    UserMsgChannel  UserMessageType = "channel"  // 频道消息副本（自己发的频道消息）
    UserMsgMention  UserMessageType = "mention"  // 频道 @提及 通知

    // 状态类
    UserMsgSub      UserMessageType = "sub"      // 订阅频道
    UserMsgUnsub    UserMessageType = "unsub"    // 取消订阅频道
    UserMsgMark     UserMessageType = "mark"     // 读取标记（包括频道和私聊）
    UserMsgAck      UserMessageType = "ack"      // 收件确认（写入发送者邮箱）

    // 快照类
    UserMsgSnapshot UserMessageType = "snapshot" // 状态快照
)

// 用户邮箱消息（统一结构）
type UserMessage struct {
    Type      UserMessageType `json:"type"`
    ID        string          `json:"id,omitempty"`  // 全局唯一消息 ID（非消息类可省略）
    Timestamp time.Time       `json:"ts"`

    // dm / channel 类型
    Direction string `json:"direction,omitempty"` // "in" 收件 / "out" 发件
    Peer      string `json:"peer,omitempty"`      // 对方：@user（私聊）或 #channel（频道）
    From      string `json:"from,omitempty"`      // 发送者（收件时使用）
    Content   string `json:"content,omitempty"`

    // mention 类型
    Inbox string `json:"inbox,omitempty"` // 来源邮箱：#channel

    // sub / mark 类型
    Inbox  string `json:"inbox,omitempty"`  // 订阅/标记的目标：#channel 或 @user
    Cursor string `json:"cursor,omitempty"` // 读取位置

    // ack 类型
    // 使用 ID 字段引用原消息

    // snapshot 类型
    State *UserState `json:"state,omitempty"`

    // 消息关系（RFC 5322）
    ReplyTo    string   `json:"reply_to,omitempty"`
    References []string `json:"references,omitempty"`
}

// 用户状态快照
type UserState struct {
    Cursors map[string]string `json:"cursors"` // inbox -> cursor（包括频道和私聊）
}

// Cursors 说明：
// - 存储所有 inbox 的读取位置
// - key: "#general" 或 "@bob"
// - value: 最后读取的消息 ID
```

| 类型 | 说明 | 存储位置 |
|------|------|----------|
| `channel` | 频道消息副本 | 自己的邮箱（自己发的） |
| `dm` | 私聊消息 | 双方邮箱 |
| `mention` | @提及 通知 | 被提及者邮箱 |

| `snapshot` | 状态快照 | 自己的邮箱 |

### 发送私聊的完整流程

```go
func SendDM(store ChatStore, from, to, content string) error {
    id := GenerateMessageID() // 全局唯一
    ts := time.Now()

    // 1. 写入发送者邮箱（发件记录）
    store.AppendUserMsg(from, &UserMessage{
        Type:      UserMsgDM,
        ID:        id,
        Ts:        ts,
        Direction: "out",
        Peer:      to,  // @bob
        Content:   content,
    })

    // 2. 写入接收者邮箱（收件记录）- 幂等
    store.AppendUserMsgIfNotExists(to, &UserMessage{
        Type:      UserMsgDM,
        ID:        id,
        Ts:        ts,
        Direction: "in",
        Peer:      from,  // @alice
        Content:   content,
    })

    return nil
}

// 接收者读取消息后，发送确认回执到发送者邮箱
func AckMessage(store ChatStore, acker, sender, msgID string) error {

    store.AppendUserMsg(sender, &UserMessage{
        Type: UserMsgAck,
        ID:   msgID,  // 引用原消息 ID

    })
    return nil
}
```

### 发送频道消息（含 @mention）

```go
func SendChannelMsg(store ChatStore, channel, from, content string, validUsers map[string]bool) error {
    id := GenerateMessageID()
    ts := time.Now()

    // 解析 @mentions（最大匹配，支持中文和全角）
    mentions := ParseMentions(content, validUsers)

    // 1. 写入频道邮箱
    store.AppendChannelMsg(channel, &ChannelMessage{
        Type:     ChannelMsgMessage,
        ID:       id,
        Ts:       ts,
        From:     from,
        Content:  content,
        Mentions: mentions,
        ReplyTo:  "",  // 可选：回复时设置
        References: nil,
    })

    // 2. 写入发送者邮箱（频道消息副本）
    store.AppendUserMsg(from, &UserMessage{
        Type:      UserMsgChannel,
        ID:        id,
        Ts:        ts,
        Direction: "out",
        Peer:      channel,
        Content:   content,
        Mentions:  mentions,
    })

    // 3. 为每个被提及者写入 mention 通知
    for _, mentioned := range mentions {
        store.AppendUserMsg(mentioned, &UserMessage{
            Type:    UserMsgMention,
            ID:      id,
            Ts:      ts,
            Inbox:   channel,
            From:    from,
            Content: content,
        })
    }

    return nil
}

// ParseMentions 解析 @mention
// 规则：
// - 最大匹配
// - @ 前必须是空格或显著标点
// - 排除邮箱格式（xxx@yyy）
// - 支持中文用户名
// - 支持全角 ＠
func ParseMentions(content string, validUsers map[string]bool) []string {
    var mentions []string
    seen := make(map[string]bool)

    // 正则：匹配 @ 或 ＠ 后跟用户名
    // 用户名字符：字母、数字、下划线、中文字符
    re := regexp.MustCompile(`(?:^|[\s,.;:!?()\[\]{}])(@|＠)([\p{L}\p{N}_]+)`)

    matches := re.FindAllStringSubmatch(content, -1)
    for _, match := range matches {
        name := match[2]
        // 最大匹配：尝试匹配更长的用户名
        for {
            if validUsers[name] && !seen[name] {
                mentions = append(mentions, name)
                seen[name] = true
                break
            }
            // 尝试更短的匹配（从后向前截断）
            if len(name) <= 1 {
                break
            }
            // 检查是否是邮箱的一部分
            name = name[:len(name)-1]
        }
    }

    return mentions
}
```

### 状态重建

```go
// 从用户邮箱重建状态
func RebuildState(user string) (*UserState, error) {
    // 1. 找到最后一个 snapshot
    snapshot := FindLastSnapshot("@" + user)
    state := snapshot.State
    if state == nil {
        state = &UserState{Cursors: make(map[string]string)}
    }
    if state.Cursors == nil {
        state.Cursors = make(map[string]string)
    }

    // 2. 只处理快照之后的 sub/unsub/mark
    for _, msg := range ReadAfter("@"+user, snapshot.Timestamp) {
        switch msg.Type {
        case UserMsgSub:
            // 订阅时，cursor 从当前最新开始（传入的 msg.Cursor）
            if msg.Cursor != "" {
                state.Cursors[msg.Inbox] = msg.Cursor
            }
        case UserMsgUnsub:
            delete(state.Cursors, msg.Inbox)
        case UserMsgMark:
            state.Cursors[msg.Inbox] = msg.Cursor
        }
    }

    return state, nil
}

// 获取指定 inbox 的 cursor
func (s *UserState) GetCursor(inbox string) string {
    return s.Cursors[inbox]
}

// 更新 cursor 并检查是否需要快照
func UpdateCursor(store ChatStore, user, inbox, cursor string) error {
    // 1. 写入 mark 消息
    store.AppendUserMsg(user, &UserMessage{
        Type:   UserMsgMark,
        Ts:     time.Now(),
        Inbox:  inbox,
        Cursor: cursor,
    })

    // 2. 检查是否需要快照（在读取操作时判断）
    return MaybeSnapshot(store, user)
}
```

### 快照触发条件

| 触发条件 | 说明 |
|---------|------|
| 读取操作 | 读取消息后检查，如果超过 N 条记录则触发 |
| 用户下线 | 保存最终状态 |
| 手动命令 | `/snapshot` 命令 |

```go
// 快照阈值
const SnapshotThreshold = 100 // 超过 100 条记录时触发快照

// 在读取操作后调用
func MaybeSnapshot(store ChatStore, user string) error {
    lastSnapshot := FindLastSnapshot("@" + user)
    count := CountAfter("@"+user, lastSnapshot.Timestamp)

    if count > SnapshotThreshold {
        state, _ := RebuildState(user)
        return store.AppendUserMsg(user, &UserMessage{
            Type: UserMsgSnapshot,
            Ts:   time.Now(),
            State: state,
        })
    }
    return nil
}
```

```go
// pkg/chat/commands.go

type InputType int

const (
    InputTypeCommand InputType = iota  // /xxx 命令
    InputTypeChannel                   // #channel xxx 频道消息
    InputTypeMessage                   // xxx 当前目标消息
)

type ParsedInput struct {
    Type    InputType
    Target  string   // 目标：#channel（仅频道消息类型）
    Content string   // 消息内容
    Command string   // 命令名（仅命令类型）
    Args    []string // 命令参数
}

func ParseInput(input string) *ParsedInput {
    input = strings.TrimSpace(input)
    if input == "" {
        return nil
    }

    // 命令：/xxx
    if strings.HasPrefix(input, "/") {
        parts := strings.Fields(input[1:])
        if len(parts) == 0 {
            return nil
        }
        return &ParsedInput{
            Type:    InputTypeCommand,
            Command: parts[0],
            Args:    parts[1:],
        }
    }

    // 频道消息：#channel xxx
    if strings.HasPrefix(input, "#") {
        parts := strings.SplitN(input[1:], " ", 2)
        if len(parts) == 2 && parts[1] != "" {
            return &ParsedInput{
                Type:    InputTypeChannel,
                Target:  "#" + parts[0],
                Content: parts[1],
            }
        }
    }

    // 当前目标消息
    return &ParsedInput{
        Type:    InputTypeMessage,
        Content: input,
    }
}
```

| 状态重建开销 | 中 | 定期 snapshot，减少回溯 |
| 优雅关闭失败 | 中 | 监听信号，确保最终快照写入 |
| 三副本不一致 | 低 | 消息 ID 唯一，幂等写入，最终一致 |
| mention 通知遗漏 | 低 | 发送时同步写入，失败则重试 |
| ID 索引失效 | 低 | 布隆过滤器假阳性时回退到扫描 |
| 文件名编码问题 | 低 | URL 编码特殊字符 |

## 消息关系模型

每条消息都有唯一的 `id`，可以通过 `reply_to` 和 `references` 建立消息关系（遵循 RFC 5322 Email 规范）。

```go
// 消息关系（参考 RFC 5322 Email 规范）
// - In-Reply-To: 单个消息 ID，表示直接回复
// - References: 消息 ID 列表，表示整个线程链

type UserMessage struct {
    // ... 现有字段
    ReplyTo    string   `json:"reply_to,omitempty"`    // 直接回复的消息 ID（单个）
    References []string `json:"references,omitempty"`  // 引用链（消息 ID 列表）
}

type ChannelMessage struct {
    // ... 现有字段
    ReplyTo    string   `json:"reply_to,omitempty"`    // 直接回复的消息 ID（单个）
    References []string `json:"references,omitempty"`  // 引用链（消息 ID 列表）
}

// 使用场景：
// 1. 回复消息：设置 reply_to，复制原消息的 references 并追加原消息 ID
// 2. 引用链：References 数组保持线程完整历史
// 3. 跨频道关联：可以引用其他频道的消息 ID
```

### 回复逻辑

```go
// 发送回复消息
func ReplyMessage(store ChatStore, inbox, from, content, replyToID string) error {
    // 1. 获取原消息
    var origMsg *ChannelMessage
    if strings.HasPrefix(inbox, "#") {
        origMsg, _ = store.GetChannelMsg(inbox, replyToID)
    }
    if origMsg == nil {
        return errors.New("original message not found")
    }

    // 2. 构建新的 references
    references := make([]string, len(origMsg.References))
    copy(references, origMsg.References)
    references = append(references, replyToID)  // 追加原消息 ID

    // 3. 创建新消息
    newMsg := &ChannelMessage{
        Type:       ChannelMsgMessage,
        ID:         GenerateMessageID(),
        ReplyTo:    replyToID,
        References: references,
        From:       from,
        Content:    content,
        Ts:         time.Now(),
    }

    return store.AppendChannelMsg(inbox, newMsg)
}
```

### 查询消息线索

```go
// 获取某条消息的所有直接回复
func GetReplies(store ChatStore, inbox, msgID string) ([]*ChannelMessage, error) {
    msgs, err := store.ReadChannelMsgs(inbox, ReadOptions{
        Types: []string{"msg"},
        Limit: 1000,
    })
    if err != nil {
        return nil, err
    }

    var replies []*ChannelMessage
    for _, m := range msgs {
        if m.ReplyTo == msgID {
            replies = append(replies, m)
        }
    }
    return replies, nil
}

// 获取完整线程（通过 References 重建）
func GetThread(store ChatStore, inbox, msgID string) ([]*ChannelMessage, error) {
    msg, err := store.GetChannelMsg(inbox, msgID)
    if err != nil || msg == nil {
        return nil, nil
    }

    // References 包含线程中所有前置消息
    thread := make([]*ChannelMessage, 0, len(msg.References)+1)

    // 获取所有引用的消息
    for _, refID := range msg.References {
        if m, err := store.GetChannelMsg(inbox, refID); err == nil && m != nil {
            thread = append(thread, m)
        }
    }

    // 追加当前消息
    thread = append(thread, msg)
    return thread, nil
}
```

## 优雅关闭

```go
// pkg/chat/chat.go

func (c *Chat) Shutdown(ctx context.Context) error {
    // 1. 停止接受新连接
    c.mu.Lock()
    c.shuttingDown = true
    c.mu.Unlock()

    // 2. 通知所有在线用户
    for _, sess := range c.sessions {
        sess.term.Write([]byte("\nServer is shutting down. Goodbye!\n"))
        close(sess.done)
    }

    // 3. 等待所有会话结束或超时
    done := make(chan struct{})
    go func() {
        for len(c.sessions) > 0 {
            time.Sleep(100 * time.Millisecond)
        }
        close(done)
    }()

    select {
    case <-done:
    case <-ctx.Done():
    }

    // 4. 为所有频道记录最终 snapshot
    for name, ch := range c.channels {
        c.store.AppendChannelMsg(name, &ChannelMessage{
            Type:    ChannelMsgSnapshot,
            Topic:   ch.Topic,
            Members: ch.Members,
            Ts:      time.Now(),
        })
    }

    // 5. 为所有在线用户记录最终 snapshot
    for name, user := range c.users {
        c.store.AppendUserMsg(name, &UserMessage{
            Type: UserMsgSnapshot,
            State: user.State,
            Ts:   time.Now(),
        })
    }

    return c.store.Shutdown()
}
```

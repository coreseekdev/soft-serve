# 01 - 架构设计

## 设计原则

1. **向后兼容**: 保留现有数据库后端代码
2. **编译时选择**: 文件系统后端 vs 数据库后端作为互斥的编译选项 (build tags)
3. **环境变量优先**: 环境变量优先级高于配置文件
4. **简化默认值**: 默认数据路径改为当前目录

## 编译选项设计

### Build Tags 结构

```
pkg/store/
├── store.go                  # 接口定义 (无 tag)
├── database/                 # 数据库实现 (tag: dbstore)
│   ├── store_dbstore.go      # -build +dbstore
│   ├── user.go
│   ├── repo.go
│   └── ...
└── file/                     # 文件系统实现 (tag: filestore)
    ├── store_filestore.go    # -build +filestore
    ├── user.go
    ├── repo.go
    └── ...
```

### 文件命名约定

```go
// pkg/store/database/store_dbstore.go
//go:build dbstore

package database

import "github.com/charmbracelet/soft-serve/pkg/store"

func NewStore(cfg *config.Config) (store.Store, error) {
    // 数据库实现
}
```

```go
// pkg/store/file/store_filestore.go
//go:build filestore

package file

import "github.com/charmbracelet/soft-serve/pkg/store"

func NewStore(cfg *config.Config) (store.Store, error) {
    // 文件系统实现
}
```

```go
// pkg/store/file/store_filestore_default.go
//go:build !dbstore

// 默认使用文件系统后端
package file

func init() {
    // 注册为默认后端
}
```

### 编译命令

```makefile
# Makefile

.PHONY: build-filestore build-dbstore

# 默认: 文件系统后端
build:
	go build -tags filestore -o soft ./cmd/soft

# 文件系统后端
build-filestore:
	go build -tags filestore -o soft-filestore ./cmd/soft

# 数据库后端
build-dbstore:
	go build -tags dbstore -o soft-dbstore ./cmd/soft

# 同时编译两个版本
build-all: build-filestore build-dbstore
```

## 配置优先级

```
┌─────────────────────────────────────────────────────────────────┐
│                         配置加载流程                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   1. 加载默认配置                                                │
│      │                                                          │
│      ▼                                                          │
│   2. 加载配置文件                                                │
│      │  SOFT_SERVE_CONFIG_LOCATION (或 {DATA_PATH}/config.yaml) │
│      │  支持 YAML 和 JSON 格式                                   │
│      ▼                                                          │
│   3. 环境变量覆盖                                                │
│      │  SOFT_SERVE_* 环境变量                                   │
│      │  优先级最高                                               │
│      ▼                                                          │
│   4. 最终配置                                                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 优先级示例

```bash
# 配置文件 config.yaml
ssh:
  listen_addr: ":2222"

# 环境变量
export SOFT_SERVE_SSH_LISTEN_ADDR=":3333"

# 最终结果: :3333 (环境变量优先)
```

## 数据路径默认值变更

### 修改前

```go
func DefaultDataPath() string {
    dp := os.Getenv("SOFT_SERVE_DATA_PATH")
    if dp == "" {
        dp = "data"  // 默认 ./data
    }
    return dp
}
```

### 修改后

```go
func DefaultDataPath() string {
    dp := os.Getenv("SOFT_SERVE_DATA_PATH")
    if dp == "" {
        dp = "."  // 默认当前目录
    }
    return dp
}
```

## 模块职责

| 模块 | 职责 | 变化 |
|------|------|------|
| `pkg/config` | 配置加载和验证 | 增强: 环境变量优先 |
| `pkg/store` | 存储接口定义 | 不变 |
| `pkg/store/database` | 数据库存储实现 | 不变 (保留) |
| `pkg/store/file` | 文件系统存储实现 | 新增 |
| `pkg/backend` | 业务逻辑 | 不变 |
| `pkg/discovery` | 仓库发现 | 新增 (filestore) |

| 功能 | FileStore | DBStore |

## 兼容性说明

### 现有用户

- 数据库后端完全兼容现有部署
- 无需迁移，继续使用 `dbstore` 编译版本

### 新用户

- 推荐使用文件系统后端
- 更简单的部署和配置

### 切换后端

- 文件系统 → 数据库: 需要手动迁移用户和配置
- 数据库 → 文件系统: 需要导出数据到目录结构

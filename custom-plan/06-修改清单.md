## 需要修改的文件

### 1. pkg/config/config.go

| 修改点 | 说明 |
|--------|------|
| `DefaultDataPath()` | **保持不变**，仍为 `"data"` |
| `UsersPath` | 新增字段，用户目录路径 |
| `ConfigPath()` | 支持 yaml/json 自动选择 |
| `Validate()` | 固定路径处理，展开 `~` |

```go
// DefaultDataPath 保持不变 (向后兼容)
func DefaultDataPath() string {
    dp := os.Getenv("SOFT_SERVE_DATA_PATH")
    if dp == "" {
        dp = "data"  // 保持原值
    }
    return dp
}

// 新增: UsersPath 字段
type Config struct {
    // ... 其他字段

    // 用户目录路径 (仅 filestore 后端)
    UsersPath string `env:"USERS_PATH" yaml:"users_path" json:"users_path"`

    // ...
}
```

### 4. Makefile

| 修改点 | 说明 |
|--------|------|
| 新增目标 | `build-filestore`, `build-dbstore`, `build-all` |


## 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 破坏 dbstore 后端 | 高 | 添加 build tags 时不修改实现代码 |
| FileStore 不完整 | 中 | 不支持的功能返回 ErrNotSupported |
| 性能差异 | 低 | 使用内存缓存 |
| 现有用户迁移 | 中 | 提供迁移脚本 |

## 回滚方案

如果出现问题：

1. **FileStore 问题**: 使用 dbstore 编译版本
2. **配置问题**: 恢复 `DefaultDataPath()` 为 `"data"`
3. **编译问题**: 移除 build tags，恢复单一后端
